# Project Architecture Rules (Non-Obvious Only)

This file provides guidance to agents when working with code in this repository.

## Architectural Constraints

- **LLM is explanation-only, never decision-making.** The architecture has a hard boundary: deterministic engines (Impact, Optimization, Cold Chain) produce structured JSON facts; Granite receives those facts and produces a human-readable explanation. Any design that lets the LLM influence a route recommendation, asset match, or cold-chain classification violates the core design principle.

- **Every engine output feeds the Evidence/Audit Layer before the Explanation Layer.** The flow is: Engine → Evidence Layer (reason codes + source rows + timestamps) → Explanation Layer. Skipping the Evidence Layer breaks the audit trail and means the explanation has no evidence to cite.

- **Offline-first is a hard constraint, not a feature.** The system must pass preflight (`scripts/preflight_demo.py`) with zero network calls. External services (watsonx.ai, Cloudant, routing APIs) are all optional with timeouts and deterministic fallbacks. Design decisions that assume network availability are incorrect.

- **Cold-chain policy profiles are data, not code.** Thresholds, duration limits, and severity rules are in `policy` dicts loaded at runtime. Do not bake any temperature numbers into engine logic. This is what allows one codebase to serve vaccines (2–8°C), biologics, food, and chemicals without code changes.

- **OR-Tools CP-SAT is the constraint solver for routing and asset assignment.** Hard constraints (reefer capability, weight capacity, delivery deadline) are modeled as `model.Add(assign[i,j] == 0)` prohibitions, not soft penalties. Violating a hard constraint by making it soft would silently produce invalid recommendations.

- **DuckDB is the single operational store** (shipments, assets, sensor logs, policy profiles, cached route graph). There is no separate relational DB for any of these. Cloudant is optional and audit-only.

- **The route graph is cached/precomputed** (Parquet). There is no live routing API call. Alternative routes are generated by removing/penalizing disrupted edges in the cached graph and re-running OR-Tools.

- **API surface follows a consistent REST pattern:**
  - `POST /api/v1/disruptions/activate` — activates a disruption scenario
  - `GET /api/v1/shipments/{shipment_id}` — shipment detail + alternatives
  - `GET /api/v1/assets/idle` — idle asset matches
  - `GET /api/v1/cold-chain/{shipment_id}/timeline` — sensor timeline + classification
  - `POST /api/v1/explanations/generate` — triggers Granite (or fallback)
  - `POST /api/v1/action-plan/export` — aggregated JSON/Markdown export
